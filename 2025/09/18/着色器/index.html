Shader简介

Shader（着色器）是一段运行在 GPU 上的程序，用来决定物体怎么被画出来。 比如物体是什么颜色、有没有反光、表面是否透明，以及是否出现发光、溶解等效果。

概念 负责什么 例子
Mesh（网格） 描述物体的几何数据：顶点、三角形、法线、UV 等 一个球的形状
Material（材质） 保存 Shader 及其使用的参数、纹理 红色、金属度、表面贴图
Shader（着色器） 定义这些数据如何参与渲染 如何计算颜色、光照和透明效果

在这个球的例子中，可以这样理解它们的关系：

  • 模型（Mesh）：提供形状，例如一个球。
  • 贴图（Texture）：提供图案，例如球表面的木纹。
  • Shader：规定如何处理光照、贴图和颜色，让球看起来像木头、金属或玻璃。
  • 材质（Material）：选择一个 Shader，并设置贴图、颜色、光滑度等具体参数，然后赋给物体。

同一个球模型，使用不同 Shader 和材质，就能呈现完全不同的外观。
同一个 Shader 可以对应多个材质：使用同一套渲染规则，给出不同的颜色和贴图，就会产生不同外观。

在 Unity 里，你可以直接使用内置 Shader，也可以用 Shader Graph 连接节点来制作效果，或者用 HLSL 写代码。
例如做一个“物体逐渐溶解”的效果，Shader 会根据噪声贴图和溶解参数，丢弃一部分片元，并给溶解边缘加上发光颜色。

ShaderLab 和 HLSL

  • ShaderLab：Unity 的 Shader 描述语言，组织属性、SubShader、Pass，以及深度、混合等渲染状态。
  • HLSL：编写实际的 GPU 计算，例如顶点变换、纹理采样和光照计算。
  • Cg、GLSL：其他着色器语言；目前使用 Unity，通常优先学习 HLSL。

Shader 变体

Shader 变体（Shader Variant）通常指同一段着色程序，在不同关键字组合下编译出来的不同版本

概念 作用
SubShader 为不同渲染管线、硬件能力等提供一套渲染实现
Pass 完成一次绘制所需的渲染状态和着色程序
Shader Variant 根据关键字选择，在编译时生成不同的着色程序版本

multi_compile和shader_feature都是声明关键字选项，让 Unity 按不同组合编译 Shader 变体。区别主要在于：构建时如何保留这些变体。

声明 变体保留方式 常见用途
multi_compile 通常保留所有声明的组合，但仍可能被其他剔除规则剔除 运行时可能切换的功能、渲染管线控制的功能
shader_feature 构建时通常只保留项目中使用到的组合，未使用的会被剔除 由材质设置决定的功能，例如是否使用法线贴图

加 local，主要改变的是关键字的作用范围，不改变变体组合数。

声明 作用范围
不加 local 可以由材质控制，也可以被同名全局关键字覆盖
加 local 由使用这个 Shader 的材质控制，不受同名全局关键字影响

以及 multi_compile_fog、multi_compile_instancing 等快捷声明。声明也可能在被包含的文件中，例如通过 #include_with_pragmas 引入。

  • 多个 SubShader 或多个 Pass，不代表它们就是多个变体。 即使只有一个 SubShader、一个 Pass，也可以产生大量变体。
  • 上述 4 个是理论组合数，实际打包保留的数量可能更少。 shader_feature 的未使用变体通常会被剔除，构建流程也可能进一步剔除变体。
  • 修改 _Color、_Speed 等普通材质参数，通常只是改变输入值，不会产生新变体；通过关键字切换编译出来的程序版本，才涉及这里说的变体。

这里理论上有两个版本：开启溶解、关闭溶解。如果构建收集到的材质都没有开启 USE_DISSOLVE，开启版本通常会被剔除。运行时再开启关键字，所需变体可能已经不在包里。
因此，运行时切换的功能需要确保相关变体被保留，或者使用 multi_compile。

注意条件分支不一定产生变体，更准确地说，是声明产生变体，条件编译让变体包含不同代码

#ifdef 在编译时就处理完了；GPU 执行时，关闭雾的版本没有这段雾代码。
而普通 if (_UseFog > 0.5) 是同一个程序里的条件判断，本身不会生成变体。

这里表达的是概念流程；GPU 可以提前执行部分深度、模板测试。

顶点着色器通常负责：

  • 把顶点位置变换到裁剪空间。
  • 传递 UV、法线、颜色等数据。
  • 修改顶点位置，实现波浪、摆动等效果。
    坐标变换的常见路径是：
    模型空间 → 世界空间 → 观察空间 → 裁剪空间。

“片元”可以先理解成一个准备画到屏幕上的像素候选，它还可能被深度测试等步骤丢弃。
片元着色器通常负责：

  • 根据 UV 采样纹理。
  • 计算颜色和光照。
  • 决定是否丢弃当前片元。
  • 输出颜色等结果到渲染目标。

三角形是图元；片元是光栅化生成的候选样本。同一个屏幕像素可能被多个物体产生的片元覆盖，并不是每个片元最终都能显示。

绘制和剔除

“画不画”和“怎么叠加”，由不同机制控制

机制 回答的问题 典型用途
Cull 剔除 三角形的哪一面需要绘制？ 剔除背面
ZTest 深度测试 当前片元能否通过深度比较？ 近处物体遮住远处物体
ZWrite 深度写入 是否把深度记录到深度缓冲？ 为后续遮挡判断提供依据
clip 透明度裁剪 是否直接丢弃当前片元？ 树叶、铁丝网、镂空图案
Stencil 模板测试 是否满足屏幕位置上的标记条件？ 遮罩、门户效果
Blend 混合 当前颜色如何与已有颜色组合？ 玻璃、烟雾、半透明 UI

其他属性

  • Render Queue：指定渲染队列，例如不透明物体常用 Geometry，半透明物体常用 Transparent。
  • RenderType：给 Shader 分类，供替换渲染等机制识别。设成 “Transparent” 本身不会自动开启透明混合。
    • 完全不写 RenderType：在内置管线中，如果相机使用 "RenderType" 做 Shader 替换，这个物体会因为缺少标签而被跳过，不出现在那次替换渲染的结果里。不是说正常画面也一定消失。
    • 内置管线的部分深度／深度法线纹理生成路径也可能使用 Shader 替换，因此标签缺失或分类错误可能影响相关效果。
    • 对于URP/HDRP可以理解为：RenderType 是供人读取的分类信息；没人读取它时，它不会自己改变绘制效果。
  • Shader LOD：配合允许的最大 Shader LOD 筛选 SubShader，通常用于限制复杂度；它不会自动根据相机距离切换网格，那属于 LODGroup 等机制。

Shader 不仅计算颜色，还要配合渲染状态，决定哪些表面参与绘制、哪些片元通过测试，以及颜色怎样叠加。
