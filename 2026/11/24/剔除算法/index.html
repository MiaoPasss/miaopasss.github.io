剔除算法

Posted on 2026-11-24 In Graphics Views:

1. 层过滤：Layer Culling

这不是复杂的几何算法，而是规则过滤。例如某台相机只绘制场景层，不绘制特效层。实现上用位掩码判断：

不匹配的对象不进入这台相机的绘制范围。Unity 的 Camera.cullingMask 就是这个用途。
特点：判断便宜，但它并不分析对象 “实际看不看得见”，只是执行你指定的规则。

2. 距离剔除：Distance Culling

可以给不同类别设置不同距离：小装饰物近一些剔除，大建筑远一些剔除。
Unity 支持 Camera.layerCullDistances；其默认判断边界是与相机对齐的平面，也可以通过 layerCullSpherical 改成球形距离边界。

距离剔除通常属于画质与性能的主动取舍，需要考虑突然消失的视觉问题。它与视锥剔除的区别是：

  • 视锥剔除：这个对象位于当前可见范围之外。
  • 距离剔除：对象可能仍在视野里，但超过了允许显示的距离。

3. 视锥剔除：Frustum Culling

它判断对象的包围体是否位于相机视锥之外。通常测试包围球、AABB 或 OBB，而不是逐个三角形测试。包围体完全在外面才剔除；与视锥相交则保留。
对象多时，可以用 BVH、八叉树等层级结构：

测试父节点包围体
├─ 完全在外面 → 整棵子树跳过
├─ 完全在里面 → 子节点不用再做该视锥测试
└─ 与边界相交 → 继续测试子节点

BVH、八叉树不是另一种可见性判断规则，而是让剔除测试更高效的数据结构。

  1. PVS：Potentially Visible Set 预计算潜在可见集
  2. 把场景划分为多个空间区域（Cell）。
  3. 离线计算：从每个区域中，哪些其他区域可能可见。
  4. 保存这些集合。
  5. 运行时找到相机所在区域，只考虑对应 PVS 中的对象或区域。
  6. 对剩余对象继续做视锥等测试。

它保存的是可能可见，不一定是 “此刻确实可见”。例如某个房间从当前区域的某个位置能看到，就可能被保留。
优点：把复杂计算转移到离线阶段。
代价：需要存储数据，而且可见性依赖用于预计算的场景结构。Unity 传统烘焙式遮挡剔除也是先生成 Cell 与可见性数据，再在运行时查询；它允许动态对象被遮挡，但动态对象不能作为该烘焙系统的遮挡者。
